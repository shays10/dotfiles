# Technical writing

Choose the document's job before editing:

- Tutorial: help a learner complete a first success.
- How-to: help a working reader complete a task.
- Reference: state exact facts, inputs, outputs, and constraints.
- Explanation: build understanding and discuss tradeoffs.

Keep one job per document or clearly separated section. Use the repository's real symbols, commands, and terminology. Address the reader directly in instructions, use active voice, keep one main thought per sentence, define necessary jargon on first use, and cut words that do not change meaning.

For procedures, put prerequisites before actions and make each step end in an observable result. For claims about behavior, inspect the implementation or authoritative source. Run documented commands when practical. Mark placeholders and unresolved facts instead of inventing them.

Preserve the existing voice unless the user asks for a rewrite. A technically accurate sentence beats a polished vague one.
